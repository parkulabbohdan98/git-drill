# Журнал git-drill

- 'git tag v1.0' - зробив закладку на коміт, щоб повернутися до ним за нею
- 'git branch feature/div' - створив гілку feature/div
- 'git checkout feature/div' - перейшов до гілки feature/div
- 'git merge feture/div' - влив гілку, отримав конфлікт
- 'git reset -- hard v1.0' - відкатив main до цього тега
- 'git reset --hard c84a5b2' - прибрав зламаний коміт з fix-reset
- 'git revert' - не стер, а створив інший який виправить 

1. Якщо тега немає, а треба знайти коміт, це робиться через git reflog — бо він показує коміти, на які вже жодна гілка не вказує.

2. revert не чіпає вказівник, а створює новий коміт, який прибирає зміни, зроблені в неправильному коміті. reset натомість пересуває вказівник гілки назад, на попередній коміт. Це небезпечно, якщо коміт уже спушений: він лишається в локальних копіях інших людей, і при наступному pull git зіллє їхню історію з моєю переписаною — неправильний коміт повернеться.

3. reflog зберігає журнал переміщень HEAD у локальному репозиторії, приблизно 90 днів, щоб можна було повернути те, що колись було закомічене. stash працює інакше: він зберігає незакомічені зміни в окремому стеку поза гілками, тому витягнути їх можна в будь-якій гілці.
